## Iface.Oik.EventDispatcher

Программа обработки и рассылки сообщений сервера «ОИК Диспетчер НТ».

Программа подключается к серверу, отслеживает появление новых событий и передает их
настроенным обработчикам: отправка на электронную почту, запись в файл, HTTP-запрос,
сообщение в Telegram и т. д.

## Документация

Документация по использованию программы приведена на портале https://iface.ru/webdocs/event/

## Запуск

Программа может работать как внешняя задача Сервера «ОИК Диспетчер НТ» или автономно на
любом удаленном компьютере.

При автономном запуске аргументы передаются в командной строке:

    Iface.Oik.EventDispatcher сервер_динамических_данных компьютер имя_пользователя пароль

Например:

    Iface.Oik.EventDispatcher TMS 10.0.0.69 admin password

При запуске в качестве внешней задачи Сервера «ОИК Диспетчер НТ» аргументы не требуются.

## Конфигурация обработчиков

Конфигурация каждого экземпляра обработчика хранится в отдельном файле с расширением `.json`
в каталоге `configs` рядом с исполняемым файлом программы. При необходимости создайте каталог
вручную.

Количество файлов не ограничено. Один и тот же обработчик может быть задействован в нескольких
конфигурациях, например, для рассылки разным получателям или записи в разные файлы.

Для конфигурации файлов используется распространенный формат [JSON](https://ru.wikipedia.org/wiki/JSON).
Допускаются комментарии (`//`, `/* ... */`) и запятые в конце списков и объектов.

Структура файла:

```json
{
  "Worker": "FileWorker",
  "Filter": {
    "Types": ["StatusChange", "Alarm"],
    "Importances": [2, 3],
    "Statuses": ["20:1:1..10"]
  },
  "Options": {
    "FilePath": "C:/events/events.txt"
  }
}
```

- `Worker` — имя обработчика из списка ниже; значение должно совпадать точно (регистр учитывается).
- `Filter` — необязательный фильтр событий (см. ниже). Если не задан, обрабатываются все события.
- `Options` — набор параметров конкретного обработчика. Имена параметров нечувствительны к регистру.

Все обработчики инициализируются при запуске программы (например, выполняется проверка соединения
с почтовым сервером и корректности токена Telegram). Если файл не удалось прочитать, он содержит
некорректный JSON, неизвестное имя обработчика или неверные параметры, программа завершится с
ошибкой и не будет запущена. Исправьте конфигурацию и запустите программу снова.

Изменения в конфигурации применяются после перезапуска программы.

### Фильтр событий

Поле `Filter` позволяет выбрать, какие события передавать обработчику. Все поля необязательны.

| Параметр      | По умолчанию | Описание                                                       |
| ------------- |--------------|----------------------------------------------------------------|
| `Types`       | все          | Типы событий, список строк (см. ниже)                          |
| `Importances` | все          | Уровни важности событий, список чисел от `0` до `3` (см. ниже) |
| `Statuses`    | пусто        | Адреса сигналов, список строк (см. ниже)                       |
| `Analogs`     | пусто        | Адреса измерений, список строк (см. ниже)                      |

#### Типы событий (`Types`):

| Значение          | Описание                |
| ----------------- |-------------------------|
| `StatusChange`    | Телесигналы             |
| `Alarm`           | Выход ТИ за уставки     |
| `Control`         | Телеуправление          |
| `Acknowledge`     | Квитирование оператором |
| `ManualStatusSet` | Ручная установка ТС     |
| `ManualAnalogSet` | Ручная установка ТИ     |
| `Extended`        | Текстовые сообщения     |

Пример: `"Types": ["StatusChange", "Alarm"]`.

#### Уровни важности событий (`Importances`):

| Значение | Обозначение | Описание                   |
| -------- | ----------- | -------------------------- |
| `0`      | ОС          | Оперативного состояния     |
| `1`      | ПС2         | Предупредительные 2        |
| `2`      | ПС1         | Предупредительные 1        |
| `3`      | АС          | Аварийные                  |

Пример: `"Importances": [2, 3]`.

#### Адреса сигналов и измерений

Задаются строками в формате
`Канал:КП:Объект`. Дополнительно можно указать диапазон объектов через `..`:

- одиночный адрес — `20:1:5`;
- диапазон — `20:1:1..10`.

Адреса можно перечислять вперемешку: `["20:1:1..10", "20:1:25"]`.

Если списки `Statuses` и `Analogs` оба пусты, фильтр по адресам не применяется. Если задан хотя
бы один из них, то события без сигнала/измерения или с адресом вне списка отбрасываются.

### Подстановки в тексте сообщения

В параметрах `Body`, `Subject`, `Url` поддерживаются следующие подстановки:

| Подстановка      | Описание                                                                        |
| ---------------- |---------------------------------------------------------------------------------|
| `{time}`         | Дата и время события                                                            |
| `{time:FORMAT}`  | Дата и время в формате .NET, например `{time:HH:mm:ss}` или `{time:dd.MM.yyyy}` |
| `{importanceId}` | Уровень важности (`0`–`3`)                                                      |
| `{importance}`   | Обозначение важности (`ОС`, `ПС2`, `ПС1`, `АС`)                                 |
| `{name}`         | Текст события                                                                   |
| `{state}`        | Состояние сигнала                                                               |
| `{type}`         | Тип события                                                                     |
| `{username}`     | Имя пользователя                                                                |
| `{tmAddr}`       | Адрес сигнала или измерения                                                     |
| `{ref}`          | Ссылка на объект или `-`, если ссылки нет                                       |
| `{defaultBody}`  | Текст события по умолчанию (см. ниже)                                           |

Текст по умолчанию формируется как:

    {time} | {importance} | {name} | {state} | {type} | {username}

Если параметр `Body` не задан, используется текст по умолчанию.

## Обработчики

На данный момент доступны следующие обработчики.

### EmailWorker

Отправляет события на электронную почту по протоколу SMTP.

| Параметр      | Обязательный | По умолчанию                       | Описание                                                              |
| ------------- | ------------ | ---------------------------------- | --------------------------------------------------------------------- |
| `Host`        | да           | —                                  | Адрес SMTP-сервера                                                     |
| `Port`        | да           | —                                  | Порт SMTP-сервера                                                     |
| `UseSsl`      | нет          | `false`                            | Использовать SSL                                                      |
| `Login`       | нет          | —                                  | Имя пользователя. Если задано, выполняется авторизация                |
| `Password`    | нет          | —                                  | Пароль                                                                |
| `From`        | да           | —                                  | Отображаемое имя отправителя                                          |
| `FromEmail`   | да           | —                                  | Адрес отправителя                                                     |
| `SendTo`      | да           | —                                  | Список адресов получателей                                            |
| `IsHtml`      | нет          | `false`                            | Отправлять письмо в формате HTML                                      |
| `Subject`     | нет          | `Новые события ОИК Диспетчер НТ`   | Тема письма, поддерживает подстановки                                 |
| `Body`        | нет          | текст по умолчанию                 | Текст письма, поддерживает подстановки                                |
| `BatchEvents` | нет          | `false`                            | Отправлять одно письмо со всеми событиями вместо письма на каждое событие |

Пример:

```json
{
  "Worker": "EmailWorker",
  "Filter": {
    "Importances": [2, 3],
    "Types": ["StatusChange", "Control", "ManualStatusSet"],
    "Statuses": ["20:1:1..10"]
  },
  "Options": {
    "Host": "smtp.mail.ru",
    "Port": 465,
    "UseSsl": true,
    "Login": "<login>",
    "Password": "<password>",
    "From": "<from>",
    "FromEmail": "<from-email>",
    "SendTo": ["<email-1>", "<email-2>"],
    "Subject": "Событие {importance}: {name}, {state}"
  }
}
```

### FileWorker

Дописывает события в текстовый файл.

| Параметр   | Обязательный | По умолчанию       | Описание                                       |
| ---------- | ------------ | ------------------ | ---------------------------------------------- |
| `FilePath` | да           | —                  | Путь к файлу. Файл открывается в режиме дописывания |
| `Body`     | нет          | текст по умолчанию | Строка, поддерживает подстановки               |

Пример:

```json
{
  "Worker": "FileWorker",
  "Filter": {
    "Statuses": ["0:1:1", "0:1:2", "0:1:10..99"],
    "Analogs": ["10:1:1", "10:1:2", "10:1:10..99"]
  },
  "Options": {
    "FilePath": "C:/events/events.txt",
    "Body": "Новое событие: {time:HH:mm:ss}, {importance}"
  }
}
```

### HttpWorker

Отправляет HTTP-запрос на заданный адрес для каждого события.

| Параметр | Обязательный | По умолчанию | Описание                                                       |
| -------- | ------------ | ------------ | -------------------------------------------------------------- |
| `Method` | да           | —            | HTTP-метод: `Get` или `Post`                                   |
| `Url`    | да           | —            | Адрес запроса, поддерживает подстановки                        |
| `Body`   | нет          | —            | Тело запроса, поддерживает подстановки. Если не задано, тело не отправляется |

Пример:

```json
{
  "Worker": "HttpWorker",
  "Filter": {
    "Types": ["Alarm"]
  },
  "Options": {
    "Method": "Post",
    "Url": "http://localhost:3000/events",
    "Body": "{\"event\":\"{defaultBody}\"}"
  }
}
```

### TelegramWorker

Отправляет события в Telegram через бота.

| Параметр   | Обязательный | По умолчанию       | Описание                             |
| ---------- | ------------ | ------------------ | ------------------------------------ |
| `BotToken` | да           | —                  | Токен Telegram-бота                  |
| `ChatIds`  | да           | —                  | Список идентификаторов чатов         |
| `Body`     | нет          | текст по умолчанию | Текст сообщения, поддерживает подстановки |

Пример:

```json
{
  "Worker": "TelegramWorker",
  "Options": {
    "BotToken": "<telegram-token>",
    "ChatIds": ["123456789"],
    "Body": "Новое событие: {time:HH:mm:ss}, {importance}"
  }
}
```

## Информация для разработчиков

Исходные коды программы являются открытыми, лицензия MIT.

Для расширения функционала можно добавить свой обработчик.

1. Добавьте класс, унаследованный от базового класса `Worker`:

```csharp
public class MyWorker : Worker
{
    protected override async Task DoWork(
        IReadOnlyCollection<TmEvent> tmEvents,
        CancellationToken stoppingToken
    )
    {
        // обработка событий
    }
}
```

2. Зарегистрируйте обработчик под нужным именем в `Program.cs`:

```csharp
services.AddKeyedTransient<Worker, MyWorker>("MyWorker");
```

После этого обработчик можно указывать в поле `Worker` файлов конфигурации.

Если обработчику нужны сервисы (например, `IOikDataApi`), добавьте их в конструктор — они
будут разрешены через механизм Dependency Injection:

```csharp
public class MyWorker : Worker
{
    private readonly IOikDataApi _api;

    public MyWorker(IOikDataApi api)
    {
        _api = api;
    }
}
```

Обязательным для реализации является метод обработки входящего (с учетом фильтра конфигурации)
списка событий:

```csharp
protected override async Task DoWork(
    IReadOnlyCollection<TmEvent> tmEvents,
    CancellationToken stoppingToken
)
{
    ...
}
```

Дополнительно можно переопределить методы конфигурирования и инициализации (например, для
проверки удаленного сервера) обработчика. Метод `Configure` вызывается при загрузке конфигурации,
`Initialize` — после него, до начала обработки событий:

```csharp
public override void Configure(WorkerOptions options)
{
    ...
}

public override async Task Initialize()
{
    ...
}
```

Для формирования текста сообщения по шаблону с подстановками используйте методы
`GetBody`, `GetBodyOrDefault` и `GetDefaultBody` базового класса.

Если ваш обработчик мог бы пригодиться другим людям, и вы готовы бы им поделиться, мы будем рады
пулл-реквесту 😀
